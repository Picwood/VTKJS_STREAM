# Production static model workflow on Linux

The native acceptance test constructs a real FeModel containing FeMesh, Material,
SolidSection and StaticStep objects. Surface traction loads are converted by the
model, and the complete deck is generated by CalculixFileWriter.WriteActiveModel.
The generator no longer assembles its own keyword list or reads authored inputs.

Run from the repository root:

```bash
python3 scripts/test-native-calculix.py
```

The script writes English and Italian decks, compares them excluding only their
random model hashes, runs native CalculiX through CaeJob and imports cube results
through production FRD/DAT readers. It exercises single/two-step cubes, a long
bar, compression and zero load. For Poisson ratio zero, an independent DAT check
compares loaded-face displacement against force * length / (modulus * width * height).
Solver prerequisites remain in [CalculiX integration](CALCULIX_INTEGRATION.md).

To generate a deck without solving:

```bash
~/.local/share/prepomax/dotnet/dotnet run \
  --project portable/tests/MeshIO.Characterization --configuration Release -- \
  --write-static-block /tmp/bar.inp 1 it-IT 2.5 1.25 0.5 2000 3.75
```

The final five arguments are length, width, height, Young's modulus and total
force. Dimensions/modulus must be finite and positive; force must be finite.
The generator supports one or two static steps. It is acceptance model assembly,
not a general modeling interface.

The current portable suite passes 3,617 checks, including repeatable complete
export, model ownership/assignments, edited loads, user keywords, state restoration
and file output. See [production writer evidence](CALCULIX_FULL_WRITER_EVIDENCE.md)
for the prepared-model boundary and remaining whole-model copying work. Project
persistence, Linux UI hosting and packaging remain separate milestones.

Native generation now includes [active mesh preparation](ACTIVE_EXPORT_EVIDENCE.md).

## Save/reopen integration (2026-09-17)

The generator saves an editable `.pma` project and reopens it before production
input export. Native acceptance attaches each solve's FRD/DAT files to that
archive and verifies reopening. See [persistence evidence](STATIC_PROJECT_PERSISTENCE.md)
for the supported model boundary and current 3,675-check suite.


The mechanical metadata case adds a sixth native solve with fixed support,
node-set forces and gravity/density. See [mechanical evidence](MECHANICAL_PROJECT_PERSISTENCE.md).
