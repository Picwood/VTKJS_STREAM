# Portable FRD import

Updated: 2026-09-14.

`FrdFileReader.ReadData` now returns a production `FeMesh`, node-to-field index
lookup, raw fields and file metadata without depending on the full `FeResults`
aggregate. The portable CaeResults project links 18 production source files.
The desktop `Read` entry point is retained in a legacy partial; it preprocesses
fields and initializes the result mesh before applying material/gap sets.

FRD coordinates, time, field values and date metadata now parse with invariant
culture. Field metadata uses its typed copy constructor instead of legacy cloning.

Validation on Linux:

- `python3 scripts/test-native-calculix.py`: the project-local CalculiX 2.23
  solves the analytic cube; production DAT and FRD readers validate the output
  in `en-US` and `it-IT`.
- FRD assertions check eight nodes, one element, node-indexed displacement
  components, magnitude, time and step. Right-face displacement is 0.001;
  left-face and transverse displacement are zero.
- The generated `portable/tests/fixtures/calculix/cube.frd` is retained from
  `cube.inp` for solver-independent regression coverage. The portable suite
  runs 354 result checks and 3,201 checks overall, including missing FRD handling.

This establishes raw mesh/field ingestion for this fixture. Full `FeResults`,
complex/modal preprocessing, other FRD element layouts, malformed-file handling,
concurrent imports and desktop visualization still need validation. The legacy
Windows build was not executed on this Linux host.

## Stress, strain and node ordering

The cube input now requests `S,E` element output. Both native acceptance and the
retained fixture verify all six stress and strain components at every node,
plus von Mises, Tresca and three principal stress values. Expected axial stress
is 1 and axial strain is 0.001; other tensor components are zero. The recorded
solver outputs 0.999960 and 0.000999960 respectively. Checks use a tolerance of
0.01% of the analytic axial value to accommodate that observed difference;
displacement checks retain their existing tighter tolerance. Element connectivity
is checked against the input's eight node labels.

A regression fixture generated by swapping two node records initially failed:
the reader assumed matching node/field record counts guaranteed matching order.
Both field parsing paths now resolve each field record's node label through the
lookup dictionary. The reordered fixture passes in both locales after the fix.
This change affects the shared production reader on Windows as well as Linux.

## Repeated beam imports

Diagnostic `ResultsForLastIterations.frd` imports previously retained a static
beam-connectivity set. A following ordinary FRD import could then silently drop
beam elements whose connectivity was already in that set. Deduplication state
is now local to each import and explicitly passed to element parsing. Duplicate
comparison sorts a cloned connectivity array, preserving the original beam
orientation instead of mutating it.

Six checks in each locale exercise diagnostic deduplication, a subsequent
ordinary import retaining both beams, original orientation in both modes, and
stable repeated diagnostic imports. The ordinary-import check failed before
the fix. Fixtures are derived from the cube node section with two reversed beam
records. This validates sequential import isolation; other global dependencies
such as unit converters still prevent claiming general concurrent-import safety.

## Partial nodal fields

FRD component arrays now initialize to `NaN` rather than zero. A mesh node
omitted from a field dataset therefore stays unknown; explicit zero records
remain zero. This follows the existing fixed-width parser's convention for
invalid numeric values. Derived displacement magnitude propagates missing data.
The shared reader's behavior changes on Windows as well as Linux.

Four assertions per locale use a derived cube fixture with node 2 omitted from
only the displacement dataset and its declared record count reduced to seven.
They verify missing components, preserved explicit zero, another node's nonzero
value and missing magnitude. The missing-value assertion failed before the fix.
Complete cube stress, strain and displacement regression checks still pass.
This does not establish desktop rendering of missing values or comprehensive
malformed/truncated FRD recovery.

## Extrema with missing samples

`FieldComponent.UpdateMaxMin` now skips `NaN` samples, including the first
sample. Previously a missing first sample poisoned the complete range. Null,
empty and all-missing arrays now produce `NaN` extrema with index -1, instead
of a stale/default range or an empty-array exception. Valid ties retain their
first sample index; infinity behavior is unchanged.

Six assertions per locale cover mixed valid/missing values, null/empty/all-missing
arrays, equal-value ties and updating a formerly valid field to all-missing.
The mixed-value assertion failed before the fix. The full suite passes 3,201
checks. Desktop consumers still need validation for the unavailable index -1;
this change does not establish rendering of wholly missing result fields.

## Native multi-step acceptance

The optional CalculiX smoke now also solves `cube-two-step.inp` in a separate
job directory to retain each solve's logs. Step two replaces the nodal load
with twice the original value. The production FRD reader validates two separate
DISP, STRESS and TOSTRAIN fields, step IDs 1/2, increment 1 and total times 1/2
in both locales. Right-face U1 doubles from 0.001 to 0.002; axial stress and
strain double within the existing solver tolerance. The first step remains
unchanged and each step has its own field object.

The generated `cube-two-step.frd` is retained for solver-independent regression
coverage. The native solve and the portable fixture checks pass. This covers
two static steps with one increment each, not nonlinear multi-increment or
complex/modal result preprocessing.

## Variable continuation records

Fixed-width field parsing now indexes actual `-1` node-record starts instead
of multiplying a node index by the first node's line count. This preserves
node mapping when some nodes use `-2` continuation records and others do not.
The previous parser crashed with an index-out-of-range exception on that layout.
Parallel value parsing is retained; each worker starts at its indexed record.

Two generated fixture variants per locale split the cube's six stress components
across lines: one splits every node, the other only the first node. Both run the
full cube mesh, displacement, stress, strain and invariant assertions. These
checks establish uniform and variable continuation handling for fixed-width
stress records; they do not establish recovery from malformed continuation lines.

## Truncated fixed-width continuations

After advancing to a continuation line, the reader now checks that a complete
12-character value is available before extracting it. An empty or incomplete
continuation stops that node's remaining component reads, leaving them `NaN`.
Previously these cases threw substring bounds exceptions from the parallel parser.

Four assertions in each locale cover empty and partially written continuation
lines. They verify missing shear components remain unknown while the preceding
axial stress and the next node's stress stay intact. The regression failed before
the fix. This is limited recovery for truncated fixed-width field continuations;
it does not establish general recovery for corrupt FRD files.
