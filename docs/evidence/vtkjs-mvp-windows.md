The process smoke is implemented by `scripts/smoke-vtkjs-winforms.ps1`. It starts the opt-in MVP, verifies that the renderer is a direct owned child and that WebView2 initializes, optionally opens a real model and observes its replacement manifest, then closes PrePoMax through its normal window workflow and asserts that the child does not survive. With `-SwitchField DISP/U1`, a temporary trigger file coordinates baseline capture with the same `SetFieldData` path used by result selection; the smoke compares every resource reference before and after. With `-ExercisePick`, a second trigger switches the controller to `-PickItem Element`, `Surface`, `GeometryEdge`, or `GeometryPoint` and generates renderer clicks; success requires a server-validated ID to appear in the controller selection buffer and the browser diagnostics to report the corresponding visible, non-overflowing overlay. With `-ExerciseAnnotation`, it creates a real measure annotation and verifies that exact callout by DOM identity and text. With `-ExerciseExtrema`, it forces both extrema visibility without mutating saved settings and requires visible Min/Max callouts containing formatted labels and node IDs; it can be combined with `-SwitchField` to verify the post-switch state. With `-ExerciseAnnotationInteraction`, it creates a non-reserved node annotation, drives browser move/edit/reset/delete messages, requires each controller mutation, and verifies the authoritative edit redraw followed by deletion. With `-ExerciseLargeSelection`, it publishes every displayed node ID and requires a shared-buffer trace plus a matching visible browser overlay count above 100,000. With `-ExerciseCameraState`, it requires stable-frame browser telemetry, a retained-state query, sequential direct-set/normal-fit/vertical-fit/adjust completion, and the corresponding ActiViz-bypass traces. With `-ExerciseBoxZoom`, it waits for a stable retained camera, drives the one-shot browser rectangle, and requires apply/completion, reduced-scale, and compatibility-bypass traces. With `-ExerciseVisibilityCamera`, it chooses an authoritative captured actor, drives real `FrmMain` hide/show, and requires both host visibility acknowledgements, browser camera completions, and hidden-adjustment bypass traces. Geometry-edge acceptance probes multiple projected positions because interior triangles are correctly ineligible. Startup automation cancels stale recovery so the explicitly requested model remains authoritative.

The direct FRD parser regression is implemented by `scripts/test-frd-complex-fixture.ps1` and runs against the freshly built production `CaeResults.dll`. Its compact source fixture is committed at `examples/complex-frequency-paired-mini.frd`; no CalculiX execution or generated rotor output is required for this check.

With `-ExerciseAnimation -AnimationMode ScaleFactor|TimeIncrements|Harmonic`, one trigger asks the real controller to build the selected animation, validates the mode and common frame count, and waits for frame 0 topology publication. A second trigger activates frame 1. The smoke requires the same scene ID with a higher revision, a mode-specific frame trace, a frame-specific hidden-camera bypass trace, changed position-resource content hashes, stable actor/render/locator counts, identical per-actor/chunk connectivity/source-point-ID/source-element-ID mappings, and stable browser activation with `cameraAdjusted=True`. `-MeasureAnimationCadence` keeps the trigger active, requests every remaining frame only after the prior revision is visible, repeats those invariants, and reports median trigger-to-manifest latency. Harmonic mode additionally requires complex result data and fails early with a specific diagnostic when it is absent.

## Scope statement

This evidence proves the application-shell seam, lifecycle, real static and deformed-result surface transfer, scale-factor, time-increment, and complex harmonic position/scalar/locator-coordinate frame deltas, compact production-reader coverage for marker-free `1PMODE` and paired complex fields, sequential large multi-actor frame publication with capture/allocation/transport/browser phase telemetry, browser stable-paint reporting, compact origin-relative Float32 parsing, shared immutable locator coordinates, in-place topology-preserving locator-BVH refit, and coordinate/scalar-only capture reuse, real point scalars and metadata, process-level component switching with scalar-only host transactions, validated node/element/part/surface/geometry-edge/point-mixed-geometry pick delivery, full-cell server-frustum and mixed-geometry area delivery, server-derived section faces/edges, pathological-cell agreement with ActiViz 5.8, authoritative small and adaptive multi-million selection overlays, interactive regular and result-extrema annotations including reset/delete/settings context actions, removal of annotation rendering from the hidden ActiViz backend, and renderer-neutral camera snapshot ownership with standard/custom/reset/normal/vertical/redraw-adjust/box-zoom/actor-visibility/animation-frame, follower, exploded-preview, and section compatibility bypass—including changed-origin full scene replacement—plus visibility, rename/color, and discrete-removal host controls. Section-aware rectangle selection and fully isoparametric curved quadratic-face cuts remain pending. Physical rendering of more than one million simultaneously matching selection points remains to be profiled; the deterministic bounded overlay path is covered by unit logic.
